# Migrate the StaticFile collector to the `SourceReader` + family-driver interface

## Motivation

StaticFile is the most generic collector — a dataset is just a manifest of file URLs (CSV/XLSX) that all land in one table — so it's a good stress test of how well the collector interface in [`docs/spec/collector-interface.md`](../spec/collector-interface.md) fits the *simplest* possible source, now that the harder ones (Socrata, DKAN, Census, TIGER) are migrated. I want it on the same footing: a `SourceReader` driven by a small family driver, running against both `PostgresEngine` and `IcebergEngine`, creating its own table via `ensure_table`, and staging with a bounded memory footprint.

It ports cleanly. The source has no catalog, so it keeps its defining trait — **no `metadata.py`** (the manifest *is* the metadata, exactly as §2 of the interface allows) — and everything else maps onto the standard pieces with no new concepts.

## Problem: what the legacy collector coupled

`StaticFileCollector` worked but entangled the usual axes plus a couple of static-specific ones:

- **Orchestration lived in the collector.** `collect(spec, force)` hard-coded the per-file loop, the already-ingested skip, and per-file tracking — source-agnostic orchestration that belongs in a shared driver.
- **DDL was generated by hand.** `generate_ddl` read the first file's header and built a PostgreSQL `CREATE TABLE` string (all-text columns + `vintage` + SCD2 apparatus), and `collect` *required the table to already exist* — a manual step every other migrated collector has dropped in favor of `ensure_table`.
- **The skip was PostgreSQL-shaped.** `_already_ingested` ran `select 1 … where vintage = … ` against the target, which only works on the physical Postgres table, not the Iceberg satellite.
- **The whole file was buffered in memory.** `client.download()` returned `bytes` and parsing wrapped `io.BytesIO`, so peak memory was the whole file — against the interface's "bounded by batch size" invariant.

## Goals and non-goals

**Goals**

- A `StaticFileReader` implementing the `SourceReader` protocol and a `run_static_collection` family driver (per-file write sessions + error isolation).
- The client streams downloads to a temp file and parses CSV/XLSX from disk, so memory is bounded by the batch, not the file.
- Same `StaticFileDatasetSpec` / `FileRef` and the same all-text schema, cp1252/leading-zero fidelity, HTML-response guard, and `file://` escape hatch.
- Reader+spec run unchanged on both engines; legacy `StaticFileCollector` and `generate_ddl` removed; tests re-laid-out with a hermetic Iceberg end-to-end run.

**Non-goals**

- A `metadata.py` (there is no catalog to explore).
- ETag/Last-Modified conditional GETs (documented follow-up if a source ever revises in place frequently).
- Changing what's stored (all columns text, `vintage` text, one row per source row).

## Design decisions

### A family driver, not `run_collection`

One spec names many files (one per vintage/edition) landing in one table — the same one-spec/many-files shape as DKAN, Census, and TIGER — so StaticFile ships `run_static_collection`. It discovers the schema from the first file, `ensure_table`s once, then collects each file into its own write session with per-file error isolation. Per-file sessions preserve the legacy per-file merge granularity (a late file failing doesn't roll back earlier files) and per-file run tracking, and the isolation is a small improvement over the legacy collector, which aborted the whole run on the first failure.

### Schema from the first file (no union)

Unlike DKAN/TIGER, the manifest's files are contractually required to share a column layout (a publisher renaming columns means the divergent edition gets its own spec/table), so there's no need to union per-file schemas — the table is created from the first file's header, matching the legacy `generate_ddl`. Extra columns in a later file are simply ignored, missing ones padded null, by the engine's write path.

### Stream to a temp file (honor the memory invariant)

The client now exposes `download_to_tempfile(url)` (streamed, retried with the standard tenacity predicate) and `parse_file(path, file_ref)` (CSV via a streaming reader, XLSX via `openpyxl` read-only) — both bounded by the batch, not the file. `file://` URLs are read in place by the reader (never downloaded, never deleted); `https` downloads land in a temp file the reader deletes after parsing. This is the one place the port is more than a mechanical move, and it brings StaticFile in line with the TIGER/Socrata file paths.

### No already-ingested skip (consistent with Census/TIGER)

The legacy `_already_ingested` skip can't be expressed portably across both engines (it depends on the physical Postgres table and dialect), and the family-driver contract forbids branching on engine type to issue storage-specific SQL — the same wall hit on Census and TIGER. So the skip is dropped in favor of SCD2 idempotency: re-collecting an unchanged edition is a no-op merge, and an in-place revision versions only the changed rows. This is the most benign place to drop it — static-file editions are small, so re-downloading the manifest each run is cheap, and the skip's real value (avoiding redundant *ingest*) is already covered by SCD2. The one caveat: **append-only** specs (`entity_key=None`) have no dedup guard, so a re-run duplicates rows — don't re-run them.

## Implementation outline

- **`spec.py`** — unchanged (`FileRef` + `StaticFileDatasetSpec(DatasetSpec)`, already on the base with construction-time validation).
- **`client.py`** — `download_to_tempfile` (streamed, tenacity retry, HTML-response guard) + `parse_file` (CSV/XLSX from disk); keeps `sanitize_column_name`, the user-agent/cookies WAF affordances, and polite throttling. In-memory `download()`/`iter_rows(bytes)` replaced.
- **`reader.py`** — `StaticFileReader`: `schema` (first file's header → all-text columns + text `vintage`), `write_mode` (SCD2 on `entity_key`, else Append), `cursor_spec` → `None`, `read` (resolve `file://` vs download-to-temp, parse, stamp `vintage`, yield batches, delete temp), `extract_cursor` → `None`.
- **`driver.py`** — `run_static_collection`: schema-from-first-file, `ensure_table`, per-file narrow → write session → `read` → `write_batch`, with per-file error isolation.
- **Remove** `collector.py`; rewrite the `README.md`.

## Testing

Under `tests/collectors/static/`:

- `test_spec.py` — unchanged (manifest validation).
- `test_client.py` — sanitization, CSV/XLSX parsing and encoding (cp1252, BOM, wrong-encoding-fails-loudly), the HTML guard, and the retry predicate — all with the real parse path, no HTTP.
- `test_reader.py` — protocol conformance, all-text schema, write-mode selection, `cursor_spec is None`, `vintage` stamping, batching, and the `file://` escape hatch (read in place, not deleted).
- `test_driver.py` — end-to-end `run_static_collection` against a hermetic `IcebergEngine`: multi-file manifest lands all vintages; leading-zero/cp1252 fidelity survives to the warehouse; re-collect is a no-op merge; an in-place revision versions only the changed row; an append-only spec duplicates on re-run; a failing file is isolated; the tracker records one run per file.

## Open questions / future work

- **Re-download on every run** (no skip). Benign here given tiny editions; if a source's files ever get large or revise frequently, ETag/Last-Modified conditional GETs (or a portable `distinct_current_values` engine primitive) are the follow-up.
- **Schema from the first file** means a manifest whose first file is unreachable can't create the table even if later files are fine — matching the legacy behavior; a caller can reorder the manifest.
