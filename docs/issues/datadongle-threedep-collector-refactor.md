# Migrate the 3DEP collector to the `SourceReader` + family-driver interface

## Motivation

3DEP is the last collector still on the legacy `Collector` shape, and it's the odd one out in two ways: its payload is **raster** (PostGIS `raster` sub-tiles sampled downstream with `ST_Value`), and its unit of work is a **multi-hundred-MB tile download**, which made the legacy "skip tiles we already hold" path genuinely valuable rather than a nice-to-have. I want it on the same footing as the migrated sources: a `ThreeDEPReader` implementing the `SourceReader` protocol from [`docs/spec/collector-interface.md`](../spec/collector-interface.md), running unchanged against both `PostgresEngine` and `IcebergEngine`, creating its own table via `ensure_table`, and keeping the bounded-memory invariant — without giving up the cheap incremental path.

## Problem: what the legacy collector coupled

`ThreeDEPCollector` worked, but only on Postgres, and it entangled the usual axes:

- **Orchestration lived in the collector.** `collect(spec, force)` hard-coded the tile loop, presence-skip, per-tile error isolation, and tracking.
- **The presence probe was PostgreSQL-shaped.** `_tile_present` ran `select 1 … where "valid_to" is null and "tile_id" like 'n42w088/%'` against the physical table — meaningless on the Iceberg satellite, and exactly the storage-specific SQL the interface forbids drivers from issuing.
- **DDL was generated by hand.** `raster_table_ddl` built a PostgreSQL `CREATE TABLE` string and `collect` required the table to already exist (the `print_ddl` workflow every migrated collector has dropped).
- **The ingest path bypassed the engine contract.** `ingest_raster_file` called Postgres's `staged_ingest` directly with hand-passed `entity_key`/`hash_exclude_columns`, rather than letting a `TableSchema` + `WriteMode` drive `open_write`.
- **The neutral type system had no raster.** `ColumnType` covered scalars, JSON, and geometry, so there was no way to even declare the target table engine-neutrally.

## Goals and non-goals

**Goals**

- A `ThreeDEPReader` implementing every `SourceReader` member, plus a `run_threedep_collection` family driver with per-tile write sessions and error isolation.
- Preserve the incremental cheap path: tiles already in the target are not re-downloaded.
- First-class raster support in the core type system and both engines, keeping the PostGIS `raster` column and the GiST `ST_ConvexHull` index that serve `ST_Value` sampling.
- Same stored shape and change-detection semantics (SCD2 keyed on `tile_id`, `checksum` as the cheap change signal, `rast` excluded from the content hash).
- Legacy `ThreeDEPCollector`, `ingest_raster_file`, and `raster_table_ddl` removed; tests re-laid-out per the interface checklist with a hermetic Iceberg end-to-end arm and a Postgres arm covering the raster COPY/`ST_Value` path.

**Non-goals**

- The 1 m project-based product (different tiling; out of scope as before).
- Raster querying on Iceberg (the WKB bytes are stored faithfully; sampling there would need a client-side WKB parser).
- `AddRasterConstraints`-style coverage invariants (same stance as the legacy DDL).

## Design decisions

### A `ColumnType.RASTER`, rendered per engine

The raster column is the whole point of the table, so typing it `TEXT` (hex-WKB as text) was a non-starter — on Postgres it would lose the `raster` type, the GiST index, and the `ST_Value` sampling path. I added `RASTER` to the neutral `ColumnType` enum, following exactly the pattern `GEOMETRY` set: values travel through the pipeline as PostGIS raster hex-WKB strings; `PostgresEngine` renders the column as `raster` (PostGIS parses hex-WKB on COPY, as it always did) and `ensure_table` now emits the GiST `ST_ConvexHull` index for any raster column (partial over current rows under SCD2, matching the legacy DDL); `IcebergEngine` stores the decoded WKB bytes as `binary`, reusing the blob handling geometry already gets (batch conversion, typed select pass-through, tombstone projection, blob hashing).

One deliberate semantic stretch, documented in the source README: `rast` is flagged `Column(metadata=True)` — not because it's bookkeeping, but because `metadata=True` is the interface's hash-exclusion mechanism, and the legacy path deliberately kept the multi-hundred-KB raster value out of the SCD2 content hash (the cheap `checksum` column — md5 of raw pixels + georeference — already carries the change signal). The alternative, a separate `hash_exclude` flag on `Column`, would be a second mechanism for the same effect; I didn't add one.

### The incremental skip becomes a real cursor (`source_tile`)

The legacy presence probe (per-tile `LIKE` against the target) can't be expressed engine-neutrally, and prior migrations (CMS, TIGER, StaticFile) resolved this tension by dropping their skips in favor of SCD2 idempotency. I considered that here and rejected it: 3DEP tiles are ~300 MB each, so "re-download everything, let SCD2 no-op it" turns every scheduled run into a multi-GB pull. The skip is the feature.

The insight that keeps it in-contract: because 1-degree tile names sort (`n42w088 < n43w088`) and tiles are processed in sorted order, "which tiles do we already hold" collapses to an ordinary high-water mark. I added a `source_tile` column (the 1-degree tile name), made it the `CursorSpec`, and an incremental read collects only tiles **strictly after** the max name in the target — read via `engine.read_high_water_mark`, a first-class engine primitive, self-healing across drop/rebuild. No presence probe, no dialect SQL, no new engine methods.

The cursor's edges, documented in the README: widening the bbox to a tile that sorts before the frontier is invisible to incremental runs (one `mode="full"` run picks it up), and a tile missing at the source that USGS later stages behind the frontier likewise needs a full run. Both are rarer and cheaper than what the legacy scheme mishandled (a run that crashed partway through a tile left it looking "present" forever until a forced run).

### A family driver for per-tile sessions, with a fail-stop rule

The shared `run_collection` would work here (the reader is fully conformant, and I kept that property), but a single write session for the whole bbox means one failed 300 MB download discards every already-staged tile. Following the TIGER precedent, `run_threedep_collection` narrows the spec per tile (`dataclasses.replace(spec, tiles=[name])`) and gives each tile its own write session and tracker run, so completed tiles persist and a crashed run resumes at the failed tile.

The cursor forced one rule the other family drivers don't need: **an incremental run stops at the first failing tile** rather than isolating and continuing. If later (larger-named) tiles merged, the high-water mark would advance past the failed tile and every future incremental run would silently skip it. Fail-stop keeps the resume self-healing; a full run isolates failures and continues, since it never consults the mark. There's a test proving the stop and the subsequent resume.

### Bounded memory, including the HWM read

The reader keeps the legacy download-to-temp-file shape (rasterio reads sub-tile windows off disk, rows are staged in small batches), so peak memory is one sub-tile. Porting to Iceberg surfaced one violation of that invariant in the engine itself: `read_high_water_mark` scanned the *entire table* into Arrow to find the max cursor value — on a raster table that means every stored blob in RAM. It now scans only the cursor column(s).

### What got deleted

`collector.py` is gone. `raster/ingest.py` is slimmed to the engine-neutral tiling half (`iter_tiles`, `RasterTile`, the checksum) — its Postgres-only `ingest_raster_file`, `raster_table_ddl`, and `tile_to_row` had no remaining users. `tests/raster/test_postgis.py` (the old direct-ingest PostGIS smoke test) is superseded by the driver tests' Postgres arm.

## Implementation outline

- **`core/schema.py`** — `ColumnType.RASTER` + `TableSchema.raster_column_names()`.
- **`engines/postgres.py`** — `RASTER → raster` type mapping; GiST `ST_ConvexHull` index in `_render_create_table`.
- **`engines/iceberg.py`** — `RASTER → binary`; raster columns join geometry on the blob paths; column-pruned `read_high_water_mark`.
- **`collectors/threedep/spec.py`** — adds `tiles: list[str] | None` (the narrowing field, validated as a subset of the bbox's tiles); everything else unchanged.
- **`collectors/threedep/reader.py`** — `ThreeDEPReader`: fixed nine-column schema, `SCD2(["tile_id"])`, `CursorSpec("source_tile")`, streaming `read` with strictly-after filtering and missing-tile skip, `extract_cursor`, plus `tiles()`/`available()` extras for the driver.
- **`collectors/threedep/driver.py`** — `run_threedep_collection`: `ensure_table`, HWM skip, per-tile narrow → session → merge, missing-at-source counting, fail-stop under incremental.
- **`client.py`/`metadata.py`** — unchanged (they already conformed).
- **README** rewritten around the explore → spec → collect workflow.

## Testing

Under `tests/collectors/threedep/` (mirroring the interface checklist):

- `test_spec.py` — validation and defaults, including the new `tiles` subset check.
- `test_client.py` — tile addressing (name/bbox/URL), offline.
- `test_metadata.py` — coverage/missing/describe against the fake client.
- `test_reader.py` — protocol conformance, schema and hash-exclusion, cursor semantics (strictly-after, frontier no-op), clipping, batching, tile-id namespacing, missing-at-source skip.
- `test_driver.py` — dual-engine end-to-end (hermetic Iceberg always; Postgres when `DWH_TEST_PG*` is set): first collect lands clipped sub-tiles; incremental skips without download; bbox widening collects only the new tile; full re-collect is a no-op; a re-staged tile versions then resettles; missing-at-source isn't fatal; full-mode failure isolation; incremental fail-stop + resume; one tracker run per tile; Postgres-only `ST_Value` sampling.

Full suite: 721 passed, 53 skipped (DB-backed arms — no test Postgres in the dev container — plus pre-existing network-marked tests).

## Open questions / future work

- **The Postgres arm needs a live run.** The dev container has no test Postgres, so the raster COPY, GiST index creation, and `ST_Value` sampling tests were written but not executed here; run them wherever `DWH_TEST_PG*` points before relying on the Postgres path.
- **Iceberg raster ergonomics.** The WKB bytes are stored faithfully but nothing reads them yet; if sampling from the Iceberg warehouse becomes a need, the follow-up is a small raster-WKB parser (the format is simple — `raster/wkb.py` already writes it).
- **Frontier-blind edge cases.** If bbox widening behind the frontier or late-staged ocean tiles turn out to happen often in practice, a portable presence primitive on the `Engine` protocol (e.g. distinct current values of a column) would restore exact per-tile presence — I deliberately didn't add one for a single caller.
